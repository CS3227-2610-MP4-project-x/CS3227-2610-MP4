# Agent workflow

The repository uses seven reusable role profiles under `workflow/agents/`, with thin platform definitions under `.codex/agents/` and `.claude/agents/`. Role contracts and platform adapters are shared across tasks; do not create a new role definition per ticket.

Start each task by checking the existing plan and handoff records. Assign one human owner (Developer A or Developer B), approved requirement IDs, exact write paths, and dependencies. Use separate worktrees for concurrent writers and never assign overlapping paths. Reuse a suitable existing worker session when available; otherwise start the same role with the current handoff as context.

The orchestrator consolidates worker notes in `workflow/handoffs/` using `workflow/agent-handoff-template.md`. Agents include shared required fields and only fields tagged for their role; they omit unrelated fields. Every worker records session resource metrics that the platform exposes; unavailable values are labeled, never estimated. The read-only frontend agent runs only for tasks that change visible UI; it gives evidence-based, specific current-to-desired recommendations. The reviewer is also read-only. At the end of the sequence, the commit/PR agent inventories all branch changes, groups eligible uncommitted work into scoped commits only with explicit human authorization, and drafts PR text. It never pushes or creates a PR. Human developers retain requirement approval, conflict decisions, push/PR decisions, and merge decisions.
